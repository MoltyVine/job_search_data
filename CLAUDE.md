# Job search extraction project

**Start here:** this repo’s `README.md` and the `job-search-extraction` skill (guided setup — `.claude/skills/job-search-extraction/SKILL.md`). Shared config: `config/participant.yaml`.

Two separate workflows live in subdirectories (more sources may be added later):

| Path | Purpose |
|------|---------|
| `gmail/` | Google Takeout Mail → dump → classify → recruiter mbox/CSV |
| `linkedin/` | LinkedIn data export → dump → classify → filtered CSV + summary |

## Environment

Python version is pinned in `.python-version` (pyenv). Run all scripts through `.venv/bin/python3` — build it once from repo root:

```bash
pyenv install -s "$(cat .python-version)"
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Never invoke a bare `python3`/`pip` on a `gmail/` or `linkedin/` script; always go through that venv so both sources share one pinned interpreter and dependency set.

## Shared config

- Example: `config/participant.example.yaml`
- Local (gitignored): `config/participant.yaml`
- Loader: `common/participant_config.py`
- Shape: `participant:` + `gmail:` / `linkedin:`
- Criteria: `docs/CLASSIFICATION_CRITERIA.md`
- Classifier: `classification.backend` in `participant.yaml`, `agent` (default) or `openrouter`. `agent` — the Claude Code agent running the pipeline reads each source’s `analysis/threads_dump.txt` directly and writes `analysis/decisions.jsonl` itself; no network call, no API key. `openrouter` — opt-in, for high-volume runs; sends thread text to OpenRouter, needs `OPENROUTER_API_KEY`

## Rules

- **Never commit** takeout zips, `.mbox` exports, LinkedIn exports, `analysis/` / `output/` contents, or `config/participant.yaml` with real PII
- Always set `participant.search_window` (inclusive start/end) in shared config — the skill asks; do not assume a year
- Classification unit: Gmail `X-GM-THRID` / LinkedIn `CONVERSATION ID`
- Keep Gmail and LinkedIn work in their respective directories
- Message content stays in this session unless the user opts into the `openrouter` classification backend — never enable it without asking first

## No AI co-authors

Never include AI or tool attribution in commit messages, PR titles, or PR bodies for this project.

Forbidden examples (non-exhaustive):

- `Co-authored-by: Claude <…>`, `Co-authored-by: Cursor <…>`, `Co-authored-by: Grok <…>`
- Any `Co-authored-by:` line naming an AI tool (Claude, Cursor, Grok, Copilot, ChatGPT, Codex, or similar)
- "Made with Claude Code", "Generated by …", or equivalent credit lines

Before `git commit`, `git commit --amend`, `git push`, or `gh pr create` / `gh pr edit`:

1. Inspect the message/body for those patterns
2. Strip them if present
3. Prefer a clean message with only human-authored summary text

If a hook or tool injects a co-author trailer on `git commit` / `git commit --amend`:

1. Do **not** push until it is gone
2. Rewrite the tip commit with `git commit-tree` + `git reset --soft` (or equivalent) so the message has **no** co-author trailer
3. Verify with `git log -1 --format=full` before push

Never put "Made with Claude Code" or similar credit in PR titles or bodies either.

## Docs and comments — new state only

When creating or editing documentation, READMEs, comments, or guides:

- Do **not** narrate or emphasize before/after diffs of the prose itself
- Focus on the **current / new state** after the change
- Prefer a short description of what the docs now say or how to use them, not a changelog of wording

This applies to agent responses about doc work and to doc content (avoid "Previously… Now…" sections unless the user asks for a migration note).
